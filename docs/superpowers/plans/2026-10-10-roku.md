# Native Roku Implementation Plan

> Use superpowers:executing-plans for integration and superpowers:dispatching-parallel-agents for independent provider and hardware work. User explicitly requested autonomous implementation, not an approval handoff.

**Goal:** Build, install and physically verify native Apex After Dark on the Philips Roku TV.

**Architecture:** A SceneGraph scene owns navigation and a single player. A persistent Task owns network, credentials, cache and persistence. Pure BrightScript functions normalize provider records, paginate and handle playback state.

**Tech Stack:** BrightScript, SceneGraph, BrighterScript compiler, brs test interpreter, Python packaging/install tooling.

**Spec:** `docs/superpowers/specs/2026-10-10-roku-design.md`

## Global constraints

- Separate repository; Fire TV files and device remain untouched.
- No secrets in source, package, logs or screenshots. No auto-provisioning without explicit account authorization.
- Actual provider content only; bounded UI results; optional failures remain optional.
- Physical verification is required for completion and must be reported accurately.

## Review focus

- Expired/failed requests return recovery actions and keep navigation usable.
- Partial catalogs never claim complete search results.
- Missing series metadata never invents episode identity.
- Back and player replacement release decoder and preserve browse state.
- Sign-out purges persistent account state; ZIP includes only intended runtime files.

### Task 1: Provider, persistence and pure data behavior

Files: `src/source/Core.brs`, `src/components/ApiTask.xml`, `src/components/ApiTask.brs`, `tests/core.brs`.
Interface: Task `request` AA `{id,op,...}` to `response` AA `{id,op,ok,items,total,hasMore,message,...}`. Commands: restore, login, pairStart, pairPoll, catalog, episodes, guide, saveProgress, favorites, signout. Entries `{id,kind,title,artwork,description,url,format,category,season,episode}`. UI pages <=30 entries.

- [ ] Write executable tests for M3U quotes/commas, unknown titles, series ordering, bounded pages, secret-free progress and invalid session rejection; observe failure.
- [ ] Implement background requests, exact source-provider contracts, registry persistence and response filtering.
- [ ] Run core tests and compiler; expected zero failures.

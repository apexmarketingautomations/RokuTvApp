# Roku implementation progress — 2026-10-10

Build **1.0.00006** is installed on the Philips H530X Roku TV. The native app is separate from the Fire TV source and uses the same authorized Apollo account through the existing backward-compatible Railway pairing contract. The saved account restored after installation without another login. The TV's active app reports 1.0.6 and Home loaded 19,594 provider movie results. Exact installed ZIP: **5,608,930 bytes**, **15 runtime files**, SHA-256 `f4dcff305feaf7c0bb7d3f039a51d1ed1f2b24ee95057330cd6c0e9a0231daf9`.

The last physical audit found a real app crash on build 1.0.5 when Details received a missing synopsis. Build 1.0.6 converts absent/blank descriptions into a safe message. The same saved episode's Details dialog then opened on the Roku and showed “Resume playback.” The Home screenshot showed Continue Watching with saved episode and movie positions, confirming that account/history survived multiple sideloaded updates. Local checks pass: core, 9 navigation assertions, 52 scene assertions, 31 Python tests, BrightScript compiler and package build.

Native build 1.0.6 episode and live-channel samples advanced **200.381 → 223.781 s** and **24.623 → 50.699 s** respectively, with no observed native error. Earlier build 4 exercised episode pause/seek and live channel switching. A&E was saved to Favorites and appeared there. These are media-state observations; changing pictures and audible sound still need direct viewer confirmation. Guide failure recovery lets a viewer watch the channel. The default Apollo EPG hostname `tvnow.best` failed DNS lookup from the development network, so actual listings could not be confirmed.

Movie playback remains a material failure. I Swear repeatedly stops near 175 seconds with native `mediaerror -5` and internal code 9. New numeric segment diagnostics recorded successful audio/video downloads for segments 21–29 immediately before that error, so the underlying demux/decoder/stream cause remains unknown. Build 1.0.6 Wake Up Dead Man and Bugonia failed during startup with native error -3. Error dialogs preserved the library and offered retry/settings/back. These outcomes block an all-green E2E claim.

Next work: diagnose or obtain provider-compatible movie streams, retest representative movies through sustained playback, confirm changing picture and audible sound for movie/episode/live classes, test a reachable XMLTV guide feed, exercise repeated exit and full TV reboot persistence, and complete broader artwork/resource/navigation checks. Keep credentials and raw provider URLs out of public evidence. See [VERIFICATION.md](VERIFICATION.md) for the test matrix and limits. Do not mark the draft PR ready or claim the app is fully working until these checks pass. Fire TV code and deployment stay untouched.
